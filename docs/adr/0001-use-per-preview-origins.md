# Use Per-Preview Origins

MoonCraft previews will use a dedicated **Preview Origin** per project instead of serving generated apps under a shared path prefix such as `/p/<preview-id>/`. The origin is project-scoped, not run-scoped; each Runtime Turn may replace the current preview process behind that origin, and MoonCraft does not expose historical run previews. Preview hostnames are assigned by deployment-owned **Preview Origin Policy**, not Runtime manifests or admin-authored Runtime JSON, so Runtime providers and admins do not need to know the public deployment host; Runtime Turns receive only local **Preview Runtime Parameters** such as port and health path. This makes generated apps behave like ordinary root-mounted web apps, avoids fragile path-prefix audits for root-relative browser URLs, and gives each project stable browser storage at the cost of wildcard DNS, TLS, and proxy routing complexity.

Because generated apps are root-mounted inside their own Preview Origin, preview audit should be simpler than the previous path-prefix audit. The platform audit verifies reachability, non-empty app responses, and known platform preview error pages; it should not statically reject root-relative browser URLs or depend on a browser/Node runtime inside the control-plane image.
