# ISS-020: Change Runtime Config secrets to object bindings

## Description
Runtime Config currently represents `secrets` as an array of `{ source, name }` objects, while `env` is a simple object map. Since Runtime Config secrets are semantics-free bindings, the admin-facing JSON should use the same map shape as `env`.

## Design
Change Runtime Config `secrets` to an object whose keys are opaque Runtime Secret names and whose values are Admin Secret source names. For example, `"secrets": { "codex_auth_json": "milky_codex_auth" }`. Keep Runtime Protocol `/init` unchanged: MoonCraft still resolves these config bindings into the existing Runtime Service `secrets` array of `{ name, value }`.

## Acceptance Criteria
- [x] SDK Runtime Config type, parser, serializer, schema, and tests use object-style `secrets`.
- [x] Control-plane secret resolution maps Runtime secret names to Admin Secret sources correctly.
- [x] Admin docs, runtime guide, and smoke scripts show the object-style Runtime Config.
- [x] No compatibility path accepts the old array-style Runtime Config.
