## Description
Replace control-plane-owned agent CLI execution with Runtime Service HTTP execution. User prompts should create asynchronous Runs through `POST /exec`, poll Run status, poll Run Events, and persist user-visible progress in MoonCraft.

## Design
MoonCraft allocates `run_id`, sends `{ run_id, prompt }`, treats `202 Accepted` as registered and queryable, polls `/runs/{run_id}` and `/runs/{run_id}/events?after=...` every 1 second, and persists events. The Run Result from `/runs/{run_id}` is the authoritative terminal outcome. Remove active Codex/Claude adapter invocation, model passing, prompt files, result files, agent session extraction, and v2 artifact assumptions from the main flow.

## Acceptance Criteria
- [ ] User prompts create v3 Runs through `POST /exec`.
- [ ] Run status supports `running`, `succeeded`, and `failed` with required messages.
- [ ] Run Events are polled with an `after` cursor and persisted for UI history.
- [ ] Duplicate `run_id` handling follows v3 idempotency semantics.
- [ ] Different `run_id` while a Run is active returns or maps `409 Conflict` correctly.
- [ ] v2 agent adapter code is no longer used for the active Runtime flow.
