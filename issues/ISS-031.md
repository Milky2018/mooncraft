## Description
`just smoke` currently verifies the fake-runtime happy path and checks that a run succeeds, a preview URL exists, preview metadata is healthy, and `/p/<preview_public_id>/api/health` is reachable.

That proves the preview health route is reachable, but it does not prove the browser-visible preview works. It does not check the preview root HTML, static resources, cache headers, browser console errors, canvas/WebGPU rendering, real Docker Runtime, real agent credentials, Git clone, commit, or push.

## Design
Keep the default smoke path lightweight, but add preview checks that catch common preview regressions without requiring a full browser or real provider credentials.

Browser-level checks can remain in a separate slower flow because they need stronger environment assumptions.

## Acceptance Criteria
- [ ] Default smoke verifies preview root HTML responds with `200`.
- [ ] Default smoke fetches at least one referenced static asset when the smoke preview exposes one.
- [ ] Default smoke verifies intended preview cache headers after ISS-030 is implemented.
- [ ] The smoke script reports a clear failure message when preview root or assets are unavailable.
- [ ] Documentation distinguishes lightweight fake-runtime smoke from real agent/browser preview validation.
