## Description
Update user/admin UI, smoke tests, and operator docs to match the source-host-backed Runtime Protocol after the backend and Runtime changes land.

## Design
Expose repository connection state and current Ready Source Commit where useful. Admin Runtime pages should configure Runtime Configs with Docker launcher, env, and opaque Runtime Secret bindings. Smoke tests should create or use a disposable Source Host repository, run through `/init` and `/exec`, verify the final commit was pushed, and verify preview through `/preview/`.

## Acceptance Criteria
- [ ] Admin UI and docs consistently use Runtime Config terminology.
- [ ] Project UI can surface Source Disconnected state.
- [ ] Project info can show repository identity and current Ready Source Commit when available.
- [ ] Smoke/E2E validates project creation, source repository binding, Runtime init, Run success with pushed commit, and preview.
- [ ] Tests no longer assert fixed preview port, workspace volume, or workspace snapshot behavior for the active flow.
