# ISS-032: Improve Runtime preview failure diagnostics

## Description
When preview startup fails, users often receive a generic unreachable message. Runtime Service has access to preview startup details, including `mooncraft-preview.sh` existence, permission errors, preview process exit status, readiness timeout, and preview logs, but those details are not consistently exposed through structured Runtime errors or admin-visible diagnostics.

This makes it hard to distinguish Runtime Service unavailable, generated preview unavailable, missing preview script, build/dependency failure, and preview process still starting.

## Design
Preserve structured preview startup failure details inside Runtime Service and expose clear Runtime Error messages to the control-plane. The control-plane should map these into actionable user-facing messages and admin logs without leaking unnecessary internal details to normal users.

Keep preview process ownership in Runtime Service.

## Acceptance Criteria
- [ ] Missing `mooncraft-preview.sh` produces a distinct preview failure reason.
- [ ] Preview script permission failure produces a distinct preview failure reason.
- [ ] Preview process early exit includes exit status and useful log tail in admin-visible diagnostics.
- [ ] Preview readiness timeout is distinguishable from Runtime Service unavailability.
- [ ] Control-plane user-facing errors remain concise while admin logs preserve the operational cause.
