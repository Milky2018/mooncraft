## Description
Implement Runtime Protocol v3 across MoonCraft. Runtime v3 treats a Runtime as a project-scoped HTTP service with a minimal manifest, Docker named volumes for durable project state, fixed service ports, asynchronous Runs, JSON event polling, and Runtime-owned preview serving.

## Design
Use `docs/runtime-protocol/README.md` and `docs/runtime-protocol/openapi.v3.yaml` as the source of truth. Do not preserve v2 compatibility unless a later issue explicitly scopes migration tooling. The control plane must stop knowing about Codex, Claude, model names, provider auth kinds, prompt files, result files, and preview scripts as protocol concepts.

## Acceptance Criteria
- [x] Runtime Protocol v3 is implemented end to end for at least one official Runtime image.
- [x] New projects can run prompts, stream/poll progress, complete, and serve preview through the Runtime Service.
- [x] v2 agent adapter and preview-script execution paths are removed from the active product flow.
- [x] Documentation and tests describe the v3 boundary rather than v2 internals.

## Close Notes
- 2026-05-28: Runtime Protocol v3 is now the active MoonCraft product flow. The control plane stores v3 manifests, starts project-scoped Runtime Service containers with Docker volumes, sends prompts through Runtime Service HTTP `/exec`, polls run status/events, and serves preview through Runtime-owned `/preview` plus port `4792`. The official runtime image implements the v3 service. Residual preview-script and fake-runtime references are confined to runtime-internal implementation details or local smoke fixtures, not platform protocol concepts.
