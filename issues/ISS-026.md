# ISS-026: Avoid reinitializing healthy Runtime Services

## Metadata
- Type: bug
- Status: open
- Priority: 1
- Labels: runtime, control-plane, lifecycle
- Assignee: unassigned
- Created: 2026-06-02
- Updated: 2026-06-02
- External ref: none

## Description
`RuntimeGateway::ensure_project_runtime_service_with_idle_refresh()` currently calls `POST /init` even when the project Runtime Service container is already running and `GET /health` is OK. The Runtime Protocol exposes health statuses such as `not_initialized`, `ready`, and `running`; the control-plane should use those statuses instead of treating every healthy container as needing initialization.

This makes a preview request or another ensure path capable of reinitializing an already ready Runtime Service, which can refresh secrets, reconfigure agent credentials, and alter the checked-out workspace even though the caller only wanted to ensure availability or refresh the idle TTL.

## Design
Change the control-plane Runtime Service supervisor so healthy containers are handled by structured health status:

- `ready`: return the endpoint and refresh idle TTL when requested.
- `running`: return the endpoint and refresh idle TTL when requested; do not call `/init`.
- `not_initialized`: call `/init`, then mark the service ready.
- unhealthy, missing, or unreachable container: recreate/start it, wait for health, then initialize once.

Do not add command-content heuristics, retry loops, or frontend workarounds. The fix belongs in the Runtime Service lifecycle boundary.

## Acceptance Criteria
- [ ] A running healthy Runtime Service with health status `ready` is not sent `POST /init`.
- [ ] A running healthy Runtime Service with health status `running` is not sent `POST /init`.
- [ ] A running healthy Runtime Service with health status `not_initialized` is sent `POST /init` exactly once by the ensure path.
- [ ] A newly created Runtime Service is still initialized before use.
- [ ] Idle TTL refresh behavior is preserved for successful ensure calls.
- [ ] Tests cover the `ready`, `running`, and `not_initialized` branches.
