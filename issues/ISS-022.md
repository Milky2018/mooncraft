# ISS-022: Do not hide create-project errors behind the New Project dialog

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: frontend, project-create, ux, error-handling
- Assignee: unassigned
- Created: 2026-06-01
- Updated: 2026-06-01
- External ref: apps/web/update.mbt

## Description
When project creation fails, the New Project dialog stays open. The error notice is rendered behind the dialog, so the user must manually close the form before seeing why creation failed.

Current failure handling keeps `new_project_modal_open: true` in `ProjectCreated(Err(error))`, while also setting the global `notice`.

## Design
Project creation failure must make the error immediately visible. Prefer closing the New Project dialog on failure so the existing global notice is visible. If preserving form context is more important, render the error inside the dialog itself; do not require the user to manually close the dialog to discover the failure.

## Acceptance Criteria
- [x] A failed create-project request makes the error visible without any extra user action.
- [x] The create button returns to a non-pending state after failure.
- [x] The UI does not leave a disabled or stale "creating" dialog over the main workspace.
- [x] Regression coverage exercises `ProjectCreated(Err(_))` and verifies the selected behavior.
