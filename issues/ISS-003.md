## Description
Add the control-plane supervisor that manages one project-scoped Runtime Service container per project using Runtime Protocol v3.

## Design
Start Runtime images through their default entrypoint, attach them to a MoonCraft-managed internal Docker network, and do not publish ports. Mount Docker named volumes at `/workspace` and `/home/mooncraft`. Track `stopped`, `ready`, and `running` Runtime Service states per project. Implement lazy recovery and idle TTL stop behavior with a default of 10 minutes and admin-configurable TTL.

## Acceptance Criteria
- [x] Control-plane can ensure a project's Runtime Service is running and healthy through `GET /health`.
- [x] Runtime containers use Docker named volumes for `/workspace` and `/home/mooncraft`.
- [x] Runtime containers are reachable by control-plane over an internal Docker network without host-published ports.
- [x] Runtime Service state and idle TTL behavior are persisted or recoverable enough for normal server operation.
- [x] Project switching and browser unload do not directly stop Runtime Services.
