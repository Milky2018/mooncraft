## Description
Update user-facing UI, admin UI, tests, and documentation to match Runtime Protocol v3 semantics after the backend and Runtime image changes land.

## Design
Admin Runtime configuration should expose only name, image, enabled/default flags, and semantics-free secrets. User project status should reflect Runtime Service state, Run status, Runtime errors, and preview readiness without agent/model-specific labels. Tests should cover v3 manifest validation, Runtime Service lifecycle, run polling, preview proxying, TTL refresh, and failure copy.

## Acceptance Criteria
- [ ] Admin Runtime UI no longer exposes agent, model, provider, or auth kind fields.
- [ ] Project info and activity views use v3 Run and Runtime Service terminology.
- [ ] Backend tests cover v3 manifest parsing, supervisor lifecycle, run execution, and preview readiness.
- [ ] Smoke or E2E tests run against the official v3 Runtime image.
- [ ] User/admin docs point to `docs/runtime-protocol/` where relevant.
