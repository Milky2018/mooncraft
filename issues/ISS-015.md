# ISS-015: Proxy preview through Runtime Service /preview/

## Description
Replace fixed preview port proxying with proxying to the Runtime Service `/preview/` subtree on the same HTTP service as Runtime Protocol APIs.

## Design
MoonCraft should route the user's Preview Origin path `/...` to the Runtime Service path `/preview/...`. The Runtime Service owns preview content and readiness. MoonCraft should not know or store a preview port and should surface Runtime preview errors without preview repair prompts.

## Acceptance Criteria
- [x] Public Preview Origin root proxies to Runtime Service `/preview/`.
- [x] Public Preview Origin subpaths proxy to matching Runtime Service `/preview/...` subpaths.
- [x] Fixed port `4792` is removed from the active preview target model.
- [x] Successful preview start requests refresh Runtime Idle TTL.
- [x] Tests cover root, asset subpath, Runtime preview error, and stopped-service lazy recovery.

## Close Notes

The official runtime service now handles `/preview/` subpaths and proxies them to its internal generated-app preview process. Verification: `moon check --warn-list +73`, `moon test --warn-list +73`, and `moon check --warn-list +73` in `docker/agent-runtime/runtime-service`.
- 2026-06-02: Preview readiness/startup is now separated from content proxying. MoonCraft calls Runtime Service `POST /preview/start` when opening the preview root, then proxies generated-application content through `GET /preview/...`.
