## Description
Implement the ADR-0007 Runtime Protocol direction. Runtime Protocol v3 should be an HTTP service contract, while Docker is only MoonCraft's first Runtime Launcher. Project source should persist in a user-owned Project Source Repository instead of Docker volumes, workspace archives, or control-plane-managed source storage.

## Design
Use `CONTEXT.md`, `docs/adr/0007-use-source-host-backed-runtime-protocol.md`, `docs/runtime-protocol/README.md`, and `docs/runtime-protocol/openapi.v3.yaml` as the source of truth. Keep the first implementation scoped to the Docker Runtime Launcher, but remove protocol assumptions about Docker paths, mounted secrets, fixed preview ports, and workspace archives from the active product flow.

## Acceptance Criteria
- [x] New projects create and bind to a user-owned Project Source Repository.
- [x] Runtime Config replaces Runtime Manifest in admin-facing language, schema, and active validation.
- [x] Runtime Service initialization uses `POST /init` with source repository data, a short-lived Project Source Credential, and Runtime Secrets.
- [x] Runs only succeed after source changes are committed and pushed to the repository default branch.
- [x] Preview traffic is proxied to Runtime Service `/preview/`, not a fixed preview port.
- [x] Legacy Docker volume, workspace archive, and mounted file-secret protocol assumptions are removed from the active product path.
