## Description
Admins need a convenient API to inspect recent platform-level logs and errors. Some failures happen before a project or run exists, so they cannot be found through project detail, run detail, or run logs.

## Design
Add a durable `admin_operation_logs` table and expose a recent-log admin endpoint. Record create-project failures through this table first, especially validation, Runtime selection, Project Source Repository creation, and source metadata persistence failures. The log API must avoid secrets and raw HTML bodies.

## Acceptance Criteria
- [x] Admin API exposes recent operation/error logs.
- [x] Operation logs include operation, level, message, optional user/project/run ids, optional status code, optional detail, and timestamp.
- [x] Create-project failures are recorded even when no project is successfully created.
- [x] Log records do not store secrets or raw gateway HTML.
- [x] Store tests cover writing and listing logs.
