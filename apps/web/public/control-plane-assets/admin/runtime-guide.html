Runtime Setup Guide

A Runtime is the app builder users choose when creating a project. As an admin, you need a name, a Docker image tag, one credential Secret, and a small Runtime JSON block.

Before You Add a Runtime

  1. Confirm the Runtime provider has published an image for your server CPU architecture.
  2. Create the credential in Admin, then Secrets.
  3. Ask the Runtime provider whether the agent is codex or claude, and which model name to use.

Add the Runtime

  1. Open Admin, then Runtimes.
  2. Click Add Runtime.
  3. Enter a user-facing name, such as Milky.
  4. Paste the Runtime JSON.
  5. Enable it when ready. Optionally make it the default for new projects.

OpenRouter Example

Create a Secret named mooncraft_ai_api_key with the OpenRouter key, then use: 

{
  "protocol_version": 2,
  "image": "docker.io/moonbitcloud/mooncraft-agent-runtime:0.3.1",
  "agent": "codex",
  "model": "openai/gpt-5.4-mini",
  "auth": {
    "kind": "openrouter_api_key",
    "secret": {
      "source": "mooncraft_ai_api_key",
      "target": {
        "type": "env",
        "name": "MOONCRAFT_AI_API_KEY"
      }
    }
  }
}

Codex Account Example

To use a Codex account instead of an API key, create a Secret named milky_codex_auth whose value is the full contents of $HOME/.codex/auth.json, then use: 

{
  "protocol_version": 2,
  "image": "docker.io/moonbitcloud/mooncraft-agent-runtime:0.3.1",
  "agent": "codex",
  "model": "gpt-5.4-mini",
  "auth": {
    "kind": "codex_auth_json",
    "secret": {
      "source": "milky_codex_auth",
      "target": {
        "type": "file",
        "path": ".codex/auth.json"
      }
    }
  }
}

Field Reference

  • image: the Docker image MoonCraft runs.
  • agent: codex or claude.
  • model: model name passed to the selected agent.
  • auth.kind: openrouter_api_key, codex_auth_json, or claude_auth_json.
  • auth.secret.source: the Admin Secret name.
  • auth.secret.target: where MoonCraft injects that Secret inside the Runtime container.
Runtime JSON does not include command lines, container users, provider fields, preview URLs, or deployment host names. MoonCraft owns those details.
